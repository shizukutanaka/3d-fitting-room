# 画像生成の接続（自分の Stable Diffusion を使う）

3D試着室は、利用者自身の環境で動いている Stable Diffusion 系
サーバに接続して、今の人物のイラストを生成できます。これは
LLM 接続（`docs/LLM-CONNECT.md`）と同じ型の機能です:
**製品にエンドポイントもモデルも含まれず、利用者が自分の
サーバを設定して初めて接続します。** 生成の計算と費用は
すべて利用者側の環境で発生し、作成者は一切関与しません。

## 1. 対象サーバ

AUTOMATIC1111 / Forge などの **WebUI API**（`/sdapi/v1`）を
公開しているサーバが対象です。サーバ側で API を有効にして
起動してください（WebUI の起動オプション `--api`。最近の
WebUI は標準で有効な場合があります）。

ブラウザから別オリジンのサーバへ接続するため、サーバ側で
CORS の許可が必要な場合があります。その場合は起動オプション
`--cors-allow-origins` にアプリの配信元オリジンを指定して
ください。認証を使う場合は `--api-auth ユーザー名:パスワード`
を設定し、アプリ側の「認証情報」欄に同じ文字列を入れます
（HTTP Basic として送られます。コロンを含まない文字列は
Bearer トークンとして送られ、ゲートウェイ配下のサーバ向け
です）。

## 2. アプリ側の設定

「AI接続」タブの下半分が画像生成の設定です。

| 項目 | 内容 |
|---|---|
| SDエンドポイントURL | サーバのルート（例: `http://localhost:7860`）。末尾に `/sdapi/v1` が付いた形でも構いません |
| 認証情報（任意） | `--api-auth` の `ユーザー名:パスワード`、または Bearer トークン |

「接続テスト」はサーバのチェックポイント一覧
（`GET /sdapi/v1/sd-models`）を取得して疎通を確認します。
生成は行いません。

設定は端末の localStorage（`fitting-room.sd.v1`）にだけ保存
されます。設定するまで、アプリは一切ネットワーク接続を
しません。

## 3. 送信されるもの

生成ボタンを押したときだけ、設定したエンドポイントへ次が
送られます。それ以外が送られることはありません。

- **プロンプト**（後述の自動構築。現在の人物パラメータと
  コーデから端末内で組み立てた英語の文章）と、固定の
  ネガティブプロンプト
- **「今の姿から生成」（img2img）の場合のみ**、現在の 3D
  描画を縮小した PNG（長辺最大 768px）

人物のシード文字列や保存データが送られることはありません。
生成された画像はアプリに戻ってきて端末内にだけ保持され、
アプリがどこかへアップロードすることはありません。

## 4. プロンプトの自動構築

プロンプトは、人物パラメータの正本（`CHARACTER_PARAM_SPECS`）
と衣服カタログから動的に組み立てられます。パラメータが
増えればプロンプトも追従します。内容は設定画面に常時表示
されるので、生成前に確認できます。

- 人物は常に「架空の成人キャラクター」として記述されます
  （法律・倫理層の判定 J-02）。性別を表す語は使いません
  （J-04: 本製品のパラメータは性別ではなく形状の値です）。
- 肌の色・身長・体型・顔立ちは、既定値から大きく外れた
  ものだけが言葉になります（ミリ・度単位の微細なオフセット
  は文章では表現できないため対象外です）。
- 髪型・髪色・瞳の色、衣服の種類と色、ポーズが続きます。
- ネガティブプロンプトは固定で、未成年を連想させる語
  （minor / child / school uniform 等）を除外します。これは
  利用者が変更できない、製品側の安全設計です。
- 「追加の言葉」欄に書いた語は末尾に足され、画風などの
  指定に使えます。

## 5. 2つの生成モード

- **今の姿から生成（img2img）**: 現在の 3D 描画を入力画像
  として生成します。その人物の顔・髪・コーデを錨にする
  ため、結果は「その人のイラスト」になります。製品上の
  主な使い道はこちらです（denoising strength は 0.65 固定）。
- **文章だけで生成（txt2img）**: プロンプトだけで生成
  します。同じ人物の再現性は img2img より弱くなります。

生成パラメータは固定です（steps 20、CFG 7、サンプラー
Euler a、txt2img は 768×768）。細かい調整は利用者自身の
サーバ側の領分として、アプリは持ちません。

## 6. 生成画像の行き先

- 画面で確認でき、PNG としてダウンロードできます。
- 「この絵でカードを作る」で、共有カードの絵として使え
  ます。カードには**生成時点の人物のシード**が埋め込まれ
  るため、そのカードから生成元の人物を復元できます
  （生成後に人物を変えても、カードは生成時点の人物を
  指します）。
- 生成画像は localStorage には保存されません（画像は保存
  先のサイズ感が違うため）。保持はメモリ上のみで、
  ダウンロードとカードが永続化の手段です。

生成画像は、利用者が自分のモデルで生成した利用者の
コンテンツです。アプリはモデルも重みも配布せず、生成画像
について権利を主張しません（`docs/DESIGN.md` §7 の台帳）。

## 7. 既知の制限

- 実在の SD サーバ（AUTOMATIC1111 / Forge 実機）との接続は
  未検証です。検証は API の形を再現したローカルスタブで
  行いました（`docs/DESIGN.md` §18）。実装ごとの細部の
  差異（認証の要否、CORS の既定値など）はサーバ側の設定に
  依存します。
- HTTPS で配信されたアプリから `http://localhost` のサーバ
  への接続は、ブラウザの制限を受ける場合があります
  （LLM 接続と同じ事情です）。
- 生成時間は利用者のサーバ側の性能に依存します。アプリ側
  のタイムアウトは 300 秒です。
