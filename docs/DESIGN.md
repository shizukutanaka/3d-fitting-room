# 3D試着室（仮称）— 設計書

- 状態: MVP 実装済み（2026-11-20）
- 正式名称: **未決定（mi の判断事項）**。本書とアプリ内では仮称「3D試着室 / 3D Fitting Room」を使う。
- 作業場所: `~/workspace/fitting-room/`（ローカル git のみ。GitHub リポジトリ作成・公開は mi の判断待ち）

## 1. 目的

アバターに服や小物を着せ替えて遊ぶ 3D アプリ。目的はニコニコ動画や
淫夢文化のような **「公開と認知」そのもの** — 利用者が着せ替えた姿を
画像にして持ち帰り、どこかで見せびらかして面白がってもらうこと。
売るものでも、集金するものでもない。

だから中核機能は着せ替えそのものより **「ワンタップで共有カード PNG を
書き出せること」** に置く。カードにはアプリ名が入り、画像が広がるほど
アプリの存在が広がる。それ以外の拡散装置（SNS 連携 API、共有 URL、
サーバー側ギャラリー等）は持たない。画像ファイル自体が媒体になる。

## 2. 設計不変条件（破ったら製品でなくなるもの）

### 2.1 金を一切絡ませない
- 広告なし、課金なし、サブスクなし、投げ銭・寄付の導線も製品内に入れない。
- 「将来収益化するためのフック」も作らない。決済・寄付・広告・サブスクの
  仕組みが **未使用のコードとしてすら存在しない** ことを
  `tests/invariants.test.ts` が文字列レベルで固定している。
- 運営コストもゼロに寄せる: バックエンドを持たないので、置き場所は
  静的ファイルの配信だけで済む（誰がどこに置いてもよい）。

### 2.2 作成者は個人データを持たない（全プロダクト共通の大原則）
- バックエンドなし、アカウントなし、解析・テレメトリなし。
- コーデの保存先は利用者端末の localStorage のみ。外部 URL の参照、
  fetch / WebSocket 等のネットワーク API の使用を
  `tests/invariants.test.ts` が禁止として固定している
  （Service Worker の fetch は同一オリジンのオフラインキャッシュ専用で、
  テストでそのガード条件も固定）。
- 書き出した PNG は端末内で合成され、端末のダウンロードとして落ちるだけ。

### 2.3 素材は権利の綺麗なものだけ
- 著作権キャラクター・権利不明の素材は使わない。
- アバターもアイテムも全てコードで組み立てる（Three.js プリミティブ）。
  テクスチャ画像・外部モデル・外部フォントはゼロ。台帳は §7。

## 3. 形態の判断

**Three.js + Vite + TypeScript の Web アプリを、インストール可能な PWA として作る。**

- スマホ・PC の両方でそのまま動き、「ホーム画面に追加」でアプリとして
  インストールできる。ストア審査もストア手数料も介在しない（＝金を
  絡ませない条件と相性がよい）。
- リポジトリ公開物はソフトウェアとして作るという方針に沿う形
  （ビルド成果物＋マニフェスト＋Service Worker のアプリ一式であり、
  単なる Web ページではない）。
- 代替案の却下理由:
  - ネイティブ（Capacitor 等）: 配布にストアが必須になり、金と審査の
    入口が増える。MVP の学び（見た目・着せ替え・書き出し）には不要。
  - 単一 HTML: 公開物の形態として認めない方針に反する。
- UI は日本語＋英語の i18n を最初から実装（辞書のキー一致をテストで固定）。

## 4. アーキテクチャ

ビルド成果物は静的ファイルのみ（`dist/`）。実行時の外部通信はゼロ。

| ファイル | 役割 |
|---|---|
| `src/main.ts` | 起動・UI 配線・状態の単一の更新経路（update → 適用＋端末内保存） |
| `src/avatar.ts` | ベースアバター（プリミティブ組み立て、ポーズ・表情、アンカー群） |
| `src/items.ts` | アイテム生成と着せ替え適用（トップス／帽子／メガネ／小物） |
| `src/scene.ts` | レンダラ・ステージ・ライト・OrbitControls |
| `src/outfit.ts` | コーデの型・検証・localStorage 保存／復元・ランダム生成 |
| `src/share.ts` | 共有カード PNG の合成とダウンロード |
| `src/i18n.ts` | 日英辞書と `t()` |
| `public/sw.js` | オフライン用アプリシェル（同一オリジン限定キャッシュ） |
| `tools/verify.cjs` | 本番ビルドのヘッドレス実走検証（Electron） |
| `tools/make_icons.py` | アイコンの手続き的生成（PIL） |

検証用に `window.__fittingRoom` ブリッジ（状態取得・設定・カード生成）を
公開している。利用者のデータではなくアプリ状態の読み書きのみ。

## 5. MVP 範囲（実装済み）

1. **ベースアバター 1 体**: 外部モデルなし、プリミティブ＋フラット
   シェーディングのローポリ調ちびキャラ。髪・顔（目・ほっぺ・口）まで
   コード生成。
2. **試着（カテゴリ 4 つ）**:
   - トップス: Tシャツ／パーカー／ワンピース × 色 7 色（袖も連動）
   - 帽子: なし／キャップ／ニット帽／ねこ耳／リボン
   - メガネ: なし／まる／しかく／サングラス
   - アクセサリー: なし／ネックレス／マフラー／バッグ
3. **カメラ・ポーズ・表情**: ドラッグ回転・ズーム（OrbitControls）、
   自動回転、視点リセット。ポーズ 5 種（ふつう／てをふる（アニメ付き）／
   バンザイ／ピース／リラックス）、表情 5 種（ふつう／にっこり／
   ウィンク／びっくり／ねむい）。
4. **共有カード書き出し（中核機能）**: 1080×1080 PNG。現在の姿を
   正方形に切り抜き、アプリ名＋タグラインを入れてダウンロード。
5. **コーデ保存**: localStorage に自動保存し、次回起動時に復元。
6. **その他**: ランダムコーデ、PWA（マニフェスト＋アイコン＋
   オフラインシェル）、レスポンシブ（スマホは下部シート、広画面は右パネル）。

非目標（MVP ではやらない）: 体型・髪型の変更、複数アバター、アイテムの
追加ダウンロード、SNS 直接投稿、共有 URL、オンラインギャラリー、
アニメーション付きポーズの拡充。

## 9. 品質引き上げ記録（2026-11-20、mi 指示「GTA6に品質を近づける。リアル寄り」）

### 9.1 変えたこと

- **アバター全面作り替え**: ローポリちびキャラ（約3頭身）→ 約7.2頭身・
  身長 1.74m のリアル寄りプロポーション。胴体・頭部は Lathe＋スプライン
  プロファイルの滑らかな形状にし、頭部は実頭比率（横 0.88／奥行 1.12）に
  変形。目・まぶた・眉・鼻・唇・耳を頭部表面に沿って配置。髪は頭蓋追従の
  シェル＋前髪＋後ろ髪＋サイドロックのボブ形状。自動まばたき（約3.6秒
  周期）と呼吸・重心の微小な揺れで「置物感」を消した。
- **質感**: PBR マテリアル化（肌 roughness 0.58、髪 0.38、布はアイテム
  側）。テクスチャは全て Canvas 手続き生成（`src/textures.ts`）:
  布の織り目（カラー＋bump）、肌、髪のストランド bump、木目床、漆喰壁、
  レザー、リブ編み bump。乱数はシード固定で再現性あり。外部素材は不使用。
- **服の作り替え**: トップス3種は胴体プロファイル追従の Lathe 形状
  （Tシャツ／フーディ／ワンピース、布テクスチャ、色違い維持）。帽子は
  頭蓋中心基準のドーム形状（キャップ／ビーニー／ねこ耳／リボン）。メガネは
  細い金属フレーム＋透明レンズ。ネックレスは胸の曲面に沿うチューブ形状
  （従来の「埋没」欠陥を回避）。バッグはレザーテクスチャ＋クロスボディ
  ストラップ。
- **空間**: パステルのデコ部屋→高級ブティックの試着室。木床
  （MeshPhysicalMaterial＋クリアコート）、漆喰壁＋パネルモールディング、
  真鍮フレーム付きの**実反射ミラー**（Reflector、1024px）、真鍮インレイ
  付き円形台座、衣類ラック（吊り服3点）、観葉植物、壁面スコーンス×2
  （鏡の反射先として正面壁を新設し、反射に映る光源にした）。
- **ライティング／描画**: ACES Filmic トーンマッピング、RoomEnvironment
  の PMREM 環境光（environmentIntensity 0.45）、PCFSoft シャドウ、
  キー／リムのスポットライト＋方向光フィル＋半球光。ポストプロセス
  （SSAO／Bloom）はモバイル負荷と共有カード書き出し経路の単純さを
  優先して見送り（この判断は 9.3 にも明記）。
- **UI パレット**: ピンク基調→真鍮×暖色ニュートラルのブティック調に
  統一（CSS 変数、共有カード背景、theme-color）。

### 9.2 設計判断: 表情セレクタの廃止

ユーザー選択式の表情（5種）は廃止し、ニュートラルなマネキン顔＋自動
まばたきに変更した。理由: リアル寄りの顔で「目を潰す／口を記号化する」
式の表情切替は即座に破綻し、不気味の谷に入る。実在の試着マネキンの
ように表情を持たない顔の方が、リアル寄りの方向では破綻がない。ポーズ
（5種）は維持。旧セーブデータの `expression` キーは読み込み時に無視
されるため互換性は保たれる（テストで固定）。

### 9.4 GTA6 との差 — 正直な棚卸し

本節は誇張を避けるための記録である。本作は「リアル寄りのマネキン試着」
であり、GTA6 本編の実写級表現とは別物である。届かない理由は技術不足
ではなく制作体制と制約の差である:

- **アセット制作体制**: GTA6 級は数千人規模・数年のモーション
  キャプチャ、フェイシャルリグ、スキャン素材、専任のライティング／
  テクスチャアーティストが前提。本作は単一のブラウザアプリで、
  全形状・全テクスチャがコード生成のみ（外部素材ゼロの不変条件）。
  顔は意図的にマネキン化しており、実在人物の表情演技は対象外。
- **描画**: 実機 GPU 前提の専用エンジンに対し、本作は WebGL
  （Three.js）の範囲。実反射は平面ミラー1枚のみで、SSAO／Bloom 等の
  ポストプロセスはモバイル破綻回避のため未投入。布の揺れ・髪の物理
  シミュレーションはない（静的形状＋ポーズのみ）。
- **アニメーション**: ポーズは関節角度の静的指定＋小さな揺れと
  まばたきのみ。歩行・着替え動作のような全身モーションはない。
- **未検証**: 実機スマホでの描画負荷・発熱・バッテリー消費、実機
  GPU でのフレームレートは未測定（検証は VM 上のソフトウェア
  レンダリングのみ）。実ブラウザ（Chrome／Safari）表示、PWA
  インストール、オフライン再訪も MVP 時点から引き続き未検証。
- **到達点の自己評価**: 「デフォルメちびキャラ」から「実寸プロポー
  ション＋PBR 質感＋実反射のあるブティック空間」へは移行できた。
  写真と見紛う水準ではなく、質の良いマネキン人形の試着体験が正確な
  表現である。
