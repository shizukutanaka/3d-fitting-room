# 3D試着室（仮称）— 「全世界に誇れるプロダクト」の要求洗い出し

- 状態: 思考と文書化のみ（実装はしていない）。2026-11-20、mi 指示
  「全世界に誇れるプロダクトに何が必要か。イーロン・マスク思考方法で
  徹底的に洗い出す」を受けて作成。
- 方法: マスク思考法（要件を疑う→削除→簡素化）＋ソクラテス問答法。
  既存文書（COMPETITIVE-ADVANTAGE.md、PERSPECTIVES.md、
  PERSPECTIVES-2.md）の結論は前提として引き継ぎ、再発見として
  出さない。本書の新規分は「誇れる」の操作的定義と、VR が主機能に
  なったことに伴う物理・性能・入口の要求、およびその実測である。
- 実測の出典: 現行コード（本体ツリー HEAD `13dfe3b`、および進行中
  レーンの worktree）、書き出し済み GLB のアクセサ集計、Meta 公式
  開発者文書、市場統計（§7 に出典一覧）。

## 1. 「誇れる」の操作的定義

「世界一」は順位の主張であり、本作の目的（公開と認知、金ゼロ）には
要らない。「誇れる」は順位ではなく**状態**であり、誰の前で・何を
示せば成立するかを先に固定する。誇る相手は4者いる:

| 相手 | その人の前で誇れるとは |
|---|---|
| 初見の利用者 | 説明を受けずに、自分のヘッドセットで、着せ替えを完了して帰れる |
| 他生態系の作り手 | 自分の道具（VRoid／VRChat／MMD 系）で本作の書き出しを開き、そのまま使える |
| 同業の開発者 | 性能の数字（実機 fps、ドローコール、バンドル量）を見て、予算内に正直に収まっていると判定できる |
| 社会（プラットフォーム・報道・保護者を含む第三者） | 成人・架空という設計原則が、説明されなくても製品の表面から読み取れる |

### 定義（正確な文）

> **「誇れる」とは、次の5点すべてが、第三者の手で再現可能な測定に
> よって示せる状態である。(1) 世界の中央値のヘッドセット
> （Quest 2）で、(2) 初見の利用者が説明なしにリンクから VR 内の
> 着せ替え完了まで到達でき、(3) その全区間でフレームが落ちず酔わ
> せず、(4) 書き出した人物ファイルが他人の道具で実際に開けて使え、
> (5) 成人・架空の設計原則が製品の表面から第三者に読み取れる。**

情緒語の排除: 「最高の体験」「美しい世界」等は本書では要求として
扱わない。測れない文は、測れる形に直すか、願望として §5 に格下げ
した。

「中央値のヘッドセット」の根拠: Quest の累計出荷は約2,676万台で、
うち Quest 2 が2,000万台（約75%）を占める（Quest 3 は326万台、
3S は175万台。§7）。つまり世界の VR 利用者の中央値は2020年発売の
Quest 2（Adreno 650）であり、「Quest 3 で快適」は世界の4分の1に
しか届かない。性能要求は全て Quest 2 を基準に置く。なお販売台数の
約3分の1しか月次利用されていないという推計もあり、「届く」ことと
「開かれる」ことは別の問題として §3-M3 で扱う。

## 2. 比較対象と水準の実測

正面から比べ、勝負になる場所と、ならない場所を分ける。

| 対象 | 「誇れる」水準で持っていて本作に無いもの | 本作が構造的に勝てる場所 | 勝負の判定 |
|---|---|---|---|
| VRChat | 同時接続約15万人規模の社会、PC で作る文化の厚み | 作成は PC の Unity＋SDK＋アカウント＋アップロード審査が前提で、**ヘッドセットの中で人物に服を着せる行為自体が存在しない**（アバターは丸ごと差し替えるもの）。本作はリンク→VR 内でアイテム単位の着せ替えが完結する | 違う勝負。社会の規模では戦わない。着せ替えの完結場所（ヘッドセット内）で戦う |
| VRChat（Quest 側の現実） | — | Quest 版アバターには硬い上限がある: 三角形2万以下・マテリアルスロット Good で2以下でないとアップロード自体ができない。本作の人物は実測 **69,628 三角形／73 メッシュ**（§4）で、VRChat Quest 基準では「存在できない」。逆に言えば本作は1人の人物に全フレーム予算を使える立場であり、上限の設計思想が違う | 数字の直接比較は無効（相手は多人数世界の1体分の予算）。ただし「73 メッシュ」という粒度は本作自身のドローコール問題として §3-M2 に効く |
| VRoid Studio＋VRoid Hub | 描画品質、スライダーの深さ、VRM の本家としての信頼 | 作成は PC アプリの中。ヘッドセット内で作って着せることはできない。本作の書き出しが VRoid Hub で実際に開けることが、相手の土俵への入場券になる（§3-M7） | 品質では負ける（既存文書の結論どおり）。「開けること」の検証で並ぶ |
| Meta アバター | ヘッドセット標準搭載、Horizon／Instagram／Messenger 横断、エディタの磨き込み | アバターは Meta の外へ出られない（外部エクスポートなし、アイテムは Meta Credits の販売網の中）。本作の人物はファイルとして出ていける | 到達範囲（標準搭載）では勝負にならない。所有と移動の自由で勝つ |
| Infinity Nikki 等の着せ替えゲーム | 衣服 **9,019 点／セット734／33カテゴリ**（ファン DB 実測）、UE5 の描画、写真モード | ガチャ収益で巨大な美術チームを雇う構造であり、点数の勝負は構造的に不可能。VR もない | 点数では戦わない（§3-D3）。「棚」の定義を点数から形状×色×回転へ置き換える |
| Picrew | 利用者7,400万人、作り手190万人、共有ループの完成度 | 2D であり VR がない。人物がファイルとして生き続ける性質もない（既存文書の結論） | 既存文書で判定済み。本書では蒸し返さない |

本書で新たに効く比較は2つだけである: (a) VRChat／VRoid／Meta の
いずれも「ヘッドセットの中で、目の前の等身大の人物に、アイテム
単位で着せ替える」体験を提供していない（作成は全て平らな画面の
道具の仕事である）。本作の主機能の定義はこの空白に正確に対応する。
(b) 性能の物差しは他人の土俵の数字（VRChat の2万三角形）ではなく、
自分の土俵の数字（Meta 公式のフレーム予算）で測るべきだ、という
判定である。

## 3. 要求の一覧

区分: **必須**（欠ければ「誇れる」と言えない）／**あると強い**／
**削除**（要求として立てないことを決めたもの。理由を残す）。
各要求に「満たしたと言える証拠」を付ける。証拠の欄が書けない
要求は要求として認めなかった。

### 3.1 必須

**M1. Quest 2 実機で、セッション全区間 72fps を維持する**
- 根拠: Meta の公式基準では対話的アプリの最低線は 72 FPS であり、
  Quest 2 は世界の中央値（§1）。VR ではフレーム落ちは「重さ」
  ではなく酔いと二度と開かれない理由になる。フレーム予算は
  72Hz で 13.9ms、90Hz で 11.1ms。
- 証拠: Quest 2 実機で、着替え操作を含む代表セッション10分間の
  フレームタイム p95 ≤ 13.9ms、再投影（ドロップ）率 1% 未満を、
  実機メトリクス（OVR Metrics 等）の記録として DESIGN.md に残す。

**M2. XR の描画予算を守り、破れる前に自動で落とす**
- 根拠: Meta の WebXR 向け指針はドローコール合計100未満が目安。
  現行シーンのコード実測（§4）はこの予算を大きく超える推計に
  なる。予算は「速い端末で測る」ものではなく「中央値で守る」
  ものであり、守れないときの劣化順序（鏡の解像度→鏡オフ→影
  オフ→描画スケール）を製品が自分で持つことが要求である。
- 証拠: 実機で `renderer.info` 相当のカウンタ（ドローコール／
  三角形）を記録し、劣化ラダーの各段が fps を割る前に発動する
  ことを Quest 2 で確認する。FFR（固定フォビエーション）の
  有効化もこの項目に含む（現行は未実装、§4）。

**M3. 入口の摩擦が秒とタップ数で測れる範囲に収まる**
- 根拠: 本作の入口はリンクである。リンク→Quest Browser→
  「VR で入る」→目の前に着た人物がいる、までの全区間が製品の
  一部である。販売台数の3分の2が眠っている市場では、入口の
  1タップと1秒がそのまま到達率になる。Meta の Web Launch
  （スマホからヘッドセットへ送る仕組み）はこの区間の公式の
  短縮路であり、未使用である。
- 証拠: 公開 URL が存在すること（現在は存在しない、§4）。
  そのうえで、Quest 2 実機・通常の Wi-Fi で、ページ読み込み
  後3アクション以内・15秒以内に VR 内の人物の前に立てること
  を、コールドスタート5回の中央値で示す。初回転送量は合計
  1MB 以下を維持する（現行 JS は約636KB／gzip 約170KB で
  射程内）。

**M4. 初見の利用者が、説明なしに最初の着せ替えを完了できる**
- 根拠: 「誇れる」の定義 (2)。VR 内パネルは 1.9m 先の文字であり、
  平らな画面の UI の常識（小さい文字、階層メニュー）は通用
  しない。完了の定義は「服1点を替える＋色1つを替える＋写真
  カードを1枚持ち帰る」。
- 証拠: 初見の Quest 利用者10人の観察テストで、セッション
  開始から90秒以内に上記3行為を完了した人数が8人以上。
  記録（所要時間と詰まった場所）を残す。

**M5. 着替えの結果が、選択の直後に目に見える**
- 根拠: 着せ替えの気持ちよさは即時性である。VR では遅延は
  「効いていない」誤認と再タップを生む。現行の着替えは形状の
  再構築を伴うため、再構築のヒッチがフレーム落ちとして出る
  危険がある（M1 と連動）。
- 証拠: 実機で計測し、選択イベント→新しい姿が表示される
  フレームまで p95 で 100ms 以下、かつ着替えに起因する
  2フレーム連続のドロップが無いこと。

**M6. カメラを製品が勝手に動かさない**
- 根拠: 酔いの最大の原因は利用者の頭と無関係なカメラ運動で
  ある。現行 VR 設計（スナップターンのみ、並進移動なし）は
  この点で正しい。それを「落とさない」ための固定要求として
  明記する。
- 証拠: コード監査で強制カメラ運動が存在しないこと、および
  M4 のテスト群でカメラ運動に起因する不快の報告がゼロで
  あること。

**M7. 書き出した VRM が、他人の道具で実際に開ける**
- 根拠: 発見の経路（素材としての採用、PERSPECTIVES.md 視点4）
  はこの1点に懸かっている。現状の検証は three.js の
  GLTFLoader 往復と公式スキーマ照合までで、実在のビューア
  での読み込みは **0件**（DESIGN.md §17.5 が明記）。「VRM
  対応」の看板はこの範囲に限る、が現行の正直な状態である。
- 証拠: 作り手が実際に使う3つ以上の外部ランタイム（VRoid
  Hub のプレビュー、VRChat の SDK アップロード可否判定、
  Cluster／VirtualCast 等の取り込みのいずれかを含む）で、
  身長・T ポーズ・ヒューマノイド骨が正しく開けることを
  人間が目で見て記録する（スクリーンショット付き）。

**M8. 世界の利用者の言語で、VR 内まで使える**
- 根拠: 現行の i18n は日英2言語・約170キー。Quest の主要市場
  は北米・欧州・日本であり、英語が共通語でも「自分の言葉で
  ない道具」は家庭用ヘッドセットでは選ばれにくい。キー数が
  約170と小さいため、言語追加は本作では安い部類の投資で
  ある（辞書の追加とパリティテストで閉じる）。
- 証拠: 対応言語を **英語・日本語・ドイツ語・フランス語・
  スペイン語・中国語（簡体）・韓国語・ポルトガル語の8言語**
  とし、全キーのパリティテスト合格に加え、VR 内パネル
  （Canvas テクスチャ文字）で CJK が Quest Browser の
  システムフォントで正しく描けることを実機で確認する。

**M9. 成人・架空の原則が、製品の表面から読み取れる**
- 根拠: 安全制限（CUS-0779）はコードの中に実装されているが、
  利用者向け文言に「成人」「架空」の明示は無い（現行フッター
  は金とデータの話だけである、§4）。カード面の架空明記は
  済んでいる。第三者（プラットフォーム審査・報道・保護者）
  の前で誇れるためには、原則は実装されているだけでは足りず
  **見えなければならない**。VR 内には現状、こうした表示の
  置き場所自体が無い。
- 証拠: フラット画面と VR 内の両方で、2アクション以内に
  「この人物は架空の成人キャラクターであり、実在の人物を
  作るためのものではない」旨の表示に到達できること。全
  対応言語で。監査スクリーンショットを残す。

**M10. 2回目以降はネットワークなしで VR まで入れる**
- 根拠: PWA のオフラインシェルは実装済みだが、VR セッション
  開始まで含めたオフライン再訪は未検証である。「いつでも
  開ける」は家庭用ヘッドセットの道具の床である。
- 証拠: 実機を機内モードにして、起動→VR 入場→着替えまで
  完了すること。

**M11. 座ったまま・片手だけで、全ての操作ができる**
- 根拠: VR の利用姿勢は立位とは限らない。現行 VR 設計の
  スポーン位置とパネル高（約1.34m）は立位前提の数値であり、
  座位（目の高さ約1.1〜1.2m）での到達性は未検証である。
- 証拠: 座位・片手コントローラのみで M4 の3行為が完了
  すること（実機）。

**M12. 30分続けても、熱とメモリで落ちない**
- 根拠: Quest 2 は熱スロットリングとブラウザタブのメモリ
  制限を持つ。「開けたが5分で落ちる」は M1 の測定（短時間）
  では捕まらない。
- 証拠: Quest 2 実機で30分連続使用し、72fps を割り込まず、
  タブが kill されないことの記録。

### 3.2 あると強い

**S1. コントローラなし（ハンドトラッキング／視線＋ピンチ）で
全操作ができる** — Meta 自身が入力の方向をそちらへ進めて
いる（VR Glasses の入力モデル）。証拠: 手だけで M4 の3行為
が完了すること。

**S2. パススルー MR モード（自分の部屋に人物が立つ）** —
Quest 3 世代の主戦場は MR であり、WebXR の immersive-ar は
Quest Browser で使える。「試着室」という部屋の看板とは別に、
「あなたの部屋に来る試着」が成立すると発見の文脈が変わる。
証拠: Quest 3 実機で、現実の部屋に等身大の人物が立ち、
着替えが完結すること。

**S3. 音がある（最小限）** — 現行の音は **ゼロ**（コードに
音声が存在しない）。VR では選択の確認が視覚だけだと「効いた
かどうか」が弱く、無音の部屋は存在感を削る。素材ゼロの
不変条件に合わせ、WebAudio の手続き生成で「選択のクリック」
「着替えの合図」「静かな室内の空気」の3点に絞る。証拠:
生成音のみで実装され、ミュートが1アクションで効くこと。

**S4. 発見面を持つ（ヘッドセット内から見つけられる）** —
現行の入口は「URL を知っている人」だけである。同じビルドを
パッケージした PWA として Horizon Store に載せる道は Meta
が公式に用意している。載せるかどうかは公開判断（mi）に
属するが、「URL を知らない人がヘッドセットの中で見つけ
られる」状態は、誇れる製品の到達条件として記録する。
証拠: ストア掲載、またはそれと等価な発見面の実在。

**S5. 既決事項の VR 側の受け皿** — 動きの書き出し＋QR
（PERSPECTIVES.md 含意2、未実装）と、共演2人
（PERSPECTIVES-2.md 視点 R2-3、未実装）は既存文書で
決着済みの方向であり、ここでは再発見として扱わない。
ただし VR では共演は人物分の描画コスト（+73 メッシュ／
約+7万三角形）をそのまま足すため、M2 の劣化ラダーが
成立した後でなければ入れられない、という依存だけを
本書の新規分として記録する。

### 3.3 削除（要求として立てない）

**D1. 「VR の中で顔・体型の細部を編集できること」** —
削除。23個のパラメータスライダーは平らな画面の仕事である。
1.9m 先のパネルにスライダー群を置くことは、判読性（M4）と
存在感の両方を壊す。役割分担は「細部はフラットで作る、
VR では着せて・見て・持ち帰る」とし、VR 内の編集は服・色・
ポーズ・コーデの選択に限る。Meta のアバターエディタが
ヘッドセット内で成立しているのはプラットフォームの資源が
あるからで、本作の物差しにはならない。

**D2. 「写実度を上げること」** — 削除（既存文書の候補Bの
再確認に加え、VR 固有の理由を足す）。等身大では様式の破綻
（めり込み・貫通・継ぎ目）が平らな画面より強く読まれる。
要求として残るのは写実度ではなく **破綻のなさ**: 全パラ
メータの端の組合せでも衣服が体を貫通しないこと。これは
測れる形（パラメータ極値の組合せでの自動撮影行列）で
別途要求になる。布・髪の物理シミュレーションも同じ理由で
要求にしない。

**D3. 「服の点数を着せ替えゲームと競うこと」** — 削除。
9,019 点はガチャ収益で雇われた美術制作ラインの産物であり、
本作の生産関数は手続き生成（形状×色×自動フィット）である。
点数の物差し自体を捨て、「棚」の定義を次の測れる形に置く:
**区別できる形状の数がカテゴリごとに5点以上・合計40点
以上**（試着室のラックに並ぶ実物の下限としての判断値。
現行は合計20点、§4）。色違いまで数えた組合せは現行でも
約103万通りあり、不足しているのは組合せではなく形状と
カテゴリのほうである。

**D4. 「120Hz を必須にすること」** — 削除。Quest 2 の
120Hz は実験的機能の扱いであり、世界の中央値の床は 72Hz
である。要求は固定値ではなく「そのセッションで合意した
レートを割り込まないこと」（M1 の形）で足りる。

**D5. 「利用者自身がアバターになる（一人称の身体化）」** —
削除。本作が着せるのは目の前の人物であり、自分の身体に
着せる一人称形式は別の製品である（VR レーンでも対象外と
記録済み）。フルボディトラッキングも同じ理由で要求に
しない。

**D6. 「同時に集まって着せ合えること（マルチプレイ）」** —

### 埋める順序の提案トップ5

1. **実機を1台、測定の土台にする**（Quest 2）。M1・M2・M3・
   M5・M10・M11・M12 の証拠はすべて実機に依存し、実機なし
   では他の全ての VR 作業が「推測の上の実装」になる。順序の
   1位は機能ではなく測定環境である。実機の用意は物理世界の
   行為であり、mi 側の手配が前提になる（この文書の側では
   測定手順と記録様式を先に用意できる）。
2. **VR レーンを統合し、描画予算の中に入れる**。ドロー
   コールの削減（小物メッシュの統合、影・鏡パスの自動劣化
   ラダー、FFR 有効化）を M1・M2 の証拠が取れる形で終える。
   主機能が出荷ツリーに無い状態を先に解消する。
3. **VRM の外部ランタイム実在検証（M7）**。実機が要らず、
   費用もかからず、発見の主張全体の前提を1つ消せる。
   順序としては最も安い「未検証の解消」である。
4. **入口を実在させて測る（M3）**。公開 URL の用意（公開
   判断は mi）と Web Launch の組み込み、コールドスタートの
   実測。測って初めて「摩擦」が設計対象になる。
5. **言語8言語化（M8）と原則の可視化（M9）**。どちらも
   実機なしで大半が進み、コストが小さく、世界の利用者と
   第三者の双方に直接効く。VR 内の表示場所は VR 統合
   （順序2）に相乗りさせる。

## 5. 正直な留保

- **この洗い出し自体が実機なしで行われている。** M1・M2 の
  「予算超過」はコード構造からの推計であり、実機の数字では
  ない。推計が外れる可能性は両方向にある（ブラウザの最適化
  で思ったより速い／WebXR の二重描画で思ったより遅い）。
  順序1位を「測定環境」としたのはこのためである。
- **fps の物差しは Meta の公式文書に依った。** WebXR
  （ブラウザ内）とネイティブアプリではオーバーヘッドが
  異なり、公式のドローコール予算は Unity 前提の表である。
  ブラウザ実行の実測が取れた時点で、予算の数値自体を
  実測側に寄せて再定義すべきである。
- **「初見テスト8/10人」「形状40点」などの閾値は判断値で
  ある。** 導出の根拠は本文に書いたが、実測データから
  逆算した値ではない。テストを実施した後に、実測で
  締め直すことを前提に置く。
- **市場数値は推計の幅がある。** Quest の台数は調査会社の
  推計（累計2,676万台、Quest 2 が2,000万台）であり、Meta の
  公式発表ではない。「中央値は Quest 2」という結論は
  推計の幅の中でも揺るがないと判断したが、絶対数そのもの
  は幅を持って読むこと。
- **本書は公開・名称・実機調達といった mi の判断事項を
  要求の形で先取りしない。** M3・S4 は「測れる状態にする」
  ことまでを要求とし、公開そのものの可否は従来どおり
  mi の判断に残す。
- 既存文書との関係: 競合優位（ファイルとしての永続と自己
  増殖）、視点0〜6 と R2-1〜R2-5、法律・倫理層の判定は
  本書でも不変であり、本書はそれらを土台に「VR が主」の
  物理と測定を足したものである。矛盾する場合は、本書の
  測定に基づく部分（§4）を現行の事実として優先し、方向性
  の判断は既存文書を優先する。

## 6. 報告のための要約

- 「誇れる」の定義: 世界の中央値のヘッドセット（Quest 2）で、
  初見の利用者が説明なしに着せ替えを完了でき、全区間で
  フレームが落ちず、書き出しが他人の道具で開け、成人・
  架空の原則が表面から読めること — の5点が第三者の再現
  可能な測定で示せる状態（§1）。
- 必須の要求: 12件（M1〜M12）。中核は実機性能（M1・M2・
  M12）、入口と初回成功の実測（M3・M4・M5）、外部検証
  （M7）、言語（M8）、原則の可視性（M9）。
- 削除と判定した代表例: VR 内での顔・体型の細部編集
  （D1、役割分担としてフラットへ）、服の点数競争（D3、
  物差しを形状40点へ置換）、120Hz 必須化（D4）、一人称の
  身体化（D5）、マルチプレイ（D6）。
- 現行との最大の差分: **主機能である VR が出荷ツリーに
  無く、実機 fps の実測値が存在しない**こと。描画は
  コード推計で既に予算超過（ドローコール約300〜450／
  フレーム vs 指針100未満）であり、拘束条件は三角形
  （69,628、予算内）ではなくドローコールとパスの掛け算
  であること。
- 順序トップ5: (1) Quest 2 実機での測定基盤、(2) VR 統合と
  描画予算の達成、(3) VRM 外部検証、(4) 入口の実在化と
  実測、(5) 8言語化と原則の可視化。
