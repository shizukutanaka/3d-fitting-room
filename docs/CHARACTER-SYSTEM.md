## 1. 「凌駕」の定義と比較

### 1.1 定義

「凌駕」を全面勝利とは定義しない。制作体制が桁違いの相手に
描画の実写度で勝てるはずがない。本システムの「凌駕」は
次の4軸で勝つことと定義する:

1. **生成の原理**: ゲームのキャラメイクは「固定骨格＋モーフ
   （あらかじめ作られた形状のブレンド）」が主流。本システムは
   全てコード生成ゆえに、**骨格そのものをパラメータから生成**
   できる。土台から違う。
2. **パラメータ空間の広さと連続性**: 系統ブレンド・非対称・
   年齢を「プリセットの切替」ではなく連続パラメータとして
   持つ。
3. **試着との統合**: 体型が変わっても衣服が自動でフィット
   する。キャラメイク単体のゲームには存在しない、試着室
   ならではの優位。
4. **共有の仕組み**: 人物をシード文字列で表し、サーバなし・
   個人データなしで共有カード経由で広げられる。ゲームの
   ギャラリーは運営サーバが前提で、本作の大原則（作成者は
   個人データを持たない）と両立しない方式は採らない。

逆に、勝てない軸は §1.3 で正直に挙げる。

### 1.3 勝てる軸・勝てない軸（結論）

**勝てる軸**:
- 骨格の生成原理（固定骨格＋モーフへの構造的な差）。
- 試着との統合（自動フィット）。キャラメイクのゲームは
  「作って終わり」で、服合わせが主目的の道具ではない。
- 共有の軽さ（シード＋カード、サーバ・登録・アカウント不要）。
  これは大原則（個人データゼロ）から自然に生まれる優位。
- 入口の軽さ（ブラウザで即時、無料、インストール不要）。

**勝てない軸**（目標から外すか近似に留める）:
- 描画の実写度。スキャン素材と専用エンジンが前提の領域で、
  コード生成のみでは届かない（棚卸しの「近似のみ」が全体の
  84%を占める事実と一致する）。
- 表情・演技の厚み（モーションキャプチャとフェイシャル
  リグの制作体制の差）。
- 本格的な布・髪の物理（自己衝突を含むものは「不可能」296件
  の主因）。
- 素材・髪型・服のライブラリ量（運営が継続追加する体制の差）。

## 2. 勝ち筋の設計

### 2.1 骨格そのものから生成する

- 仕組み: 骨長と比率のパラメータベクトルから関節位置を算出
  し、体表プロファイル（現行の Lathe 制御点列）を骨格に
  従属させる。現行コードは既に「プロファイル列→回転体」と
  いう生成構造を持っており、これを「固定プロファイル」から
  「骨格パラメータで駆動されるプロファイル」へ一般化する。
- なぜ勝てるか: ゲーム側はアセット保護とアニメーション
  資産の再利用のため骨格を固定せざるを得ない。本作は
  アニメーション資産を持たない（弱みでもある）が、裏返せば
  骨格を固定する理由がない。
- 作れる範囲: 骨長・比率の可変と、それに連動する体表・
  アンカー・衣服の再生成まで。「可能〜近似」。解剖学的に
  正確な骨形状そのものは作らない（体表に出ない内部構造に
  制作資源を割かない判断）。
- 対応する棚卸し: SKE 骨・長さ／太さ系 412 件、BDY 身長連動
  24 件。

### 2.2 民族系統の連続ブレンド

- 仕組み: 系統を「完成品プリセット」ではなく、特徴ごと
  （肌色、目の形、鼻、唇、頬骨、髪質…）の分布パラメータと
  して持ち、特徴ごとに混合率を指定して合成する。GTA Online
  の遺伝（両親ブレンド）を、特徴単位・N系統へ一般化した形。
- なぜ勝てるか: 多くのゲームは系統をプリセット選択で済ま
  せる。本作は特徴単位の混合率まで連続化する。
- 作れる範囲: 肌色・色調は「可能」。顔立ち・髪質は「近似
  のみ」（プリミティブ顔の解像度の限界）。扱いは
  LEGAL-ETHICS.md 判断 J-01（条件付き許可）に従う: 系統は
  内部の分布参照としてのみ保持し、UI に国籍・民族名の
  ラベルを出さない（系統は分布の参照であって国籍ラベル
  付き完成品にしない）。

### 2.3 左右非対称の導入

- 仕組み: 全ての対パラメータに左右差（Δ）軸を持たせる。
  実在の顔と体は非対称であり、完全対称は「作り物感」の
  主要因のひとつ。自然な範囲のランダム非対称を初期値に
  混ぜる。
- なぜ勝てるか: 非対称編集を持つゲームは少数（inZOI、
  黒い砂漠等）で、体全体に一貫した非対称軸を持つものは
  さらに少ない。
- 作れる範囲: 「可能」。パラメータ構造の問題であり、描画
  技術の問題ではない。対応: FAC 左右差系 144 件（12パラ
  メータ×12系統）＋ BDY 左右差系。

### 2.4 年齢の連続変化

- 仕組み: 年齢パラメータ（連続値）が、骨格（姿勢・脊柱の
  湾曲）、体型（脂肪分布）、皮膚（しわ・たるみ・色調）に
  連動する。年齢「区分」ではなく連続であることが差。
- 作れる範囲: 「近似のみ」。皮膚テクスチャ側の連動と姿勢
  の連動は届くが、成長（若年層の体格変化）まで含めるかは
  GAP-ANALYSIS.md §4 の論点3（安全・倫理面の判断事項）
  であり、本設計では成人の範囲内の連続変化を対象とする。
  範囲の具体化は LEGAL-ETHICS.md 判断 J-02 に従う: 下限は
  外見年齢20歳相当とし、年齢パラメータは遺伝合成の対象
  に含めない（J-06）。

### 2.5 2体からの「遺伝」合成とシード共有

- 仕組み: 人物全体をパラメータベクトルとしてシード文字列
  に符号化する（端末内のみで生成・保存）。2体のベクトルを
  特徴グループごとの混合率で補間すれば「遺伝」になる。
  共有は既存の共有カード（PNG）にシードを併記／埋め込む
  形で、受け取った側が端末内で再現する。サーバは要らない。
  **（2026-11-20 実施済み）**: カードへの埋め込みは実装
  された。PNG の tEXt チャンク（キーワード
  `FittingRoomSeed`）にシードを入れ、カード面にもシード
  文字列と「この人物は架空のキャラクターです」を印字する。
  受け取り側はカード画像のドロップ／ファイル選択で復元
  できる。**正直な技術注記**: PNG チャンクはファイル直送
  では保持されるが、SNS 等の再圧縮・再エンコードで剥が
  れる場合がある。その場合の受け皿が、カード面に印字
  されたシード文字列（目で読んで貼り付けフォームに
  入力する）である。詳細は DESIGN.md §12。
  **（2026-11-20 実施済み）**: 遺伝合成も実装された。
  パラメータごとに決定的 PRNG（合成用シード）で「Aから
  継承／Bから継承／中間ブレンド」を選び、離散値（パレット
  色・髪型）は継承のみとする。結果は必ず sanitize を
  通るため安全制限 CUS-0779 が子にも自動で効き、通常の
  シードとして共有カードにも乗る。コマンド層の
  `blend_characters` でエージェントからも量産できる。
  衣服は合成対象外（現在のコーデを維持）、出自はどこにも
  記録しない。詳細は DESIGN.md §16。
- なぜ勝てるか: ゲームの共有は運営サーバのギャラリーが
  前提。本作は「画像ファイル自体が媒体」という既存の製品
  設計（DESIGN.md §1）と直結し、大原則と矛盾しない。
- 作れる範囲: 「可能」。対応: CUS システム系のシード・
  遺伝系 7 件＋パラメータの対象化 747 件。法律・倫理条件は
  LEGAL-ETHICS.md 判断 J-06（遺伝: 合成結果は成人として
  提示し年齢パラメータを含めない）・J-07（シード共有:
  共有カードに架空の人物である旨を明記する）に従う。

### 2.6 試着との統合（自動フィット）

- 仕組み: 現行の衣服生成は「体プロファイル＋約11mmオフ
  セット」という生成方式であり、体型パラメータが変われば
  オフセット元を差し替えて再生成できる。つまり自動フィット
  は現行アーキテクチャの一般化として設計できる。フィット
  結果はサイズ表示（S/M/L 等）に翻訳して「試着」らしく見せる。
- なぜ勝てるか: キャラメイクのゲームに試着という概念が
  ない。本作の存在理由そのものが優位になる唯一の軸。
- 作れる範囲: 「近似のみ」（布の物理的なフィットではなく
  形状の追従）。対応: CLO フィット系＋CUS 自動フィット系。

### 2.7 物理のメイク時プレビュー

- 仕組み: 本格物理ではなく、近似物理（小物の回転バネ、髪の
  遅延追従、裾の揺れ）をメイク画面でそのまま見せる。作った
  人物が「動いたときどう見えるか」を作る時点で確認できる。
- 作れる範囲: 「近似のみ」。自己衝突・本格布は §6 のとおり
  目標から外す。対応: PHY 小物 32 件・髪 36 件が中心。

## 3. パラメータ空間の構造

### 3.1 棚卸し 9,034 項目の写像

### 3.2 階層と依存関係

```
L0 系統ブレンド（特徴ごとの混合率）
 └─ L1 骨格（骨長・比率・関節位置）        ← 全ての土台
     └─ L2 体型（脂肪・筋肉・姿勢・年齢）   ← L1に従属
         └─ L3 顔（頭部形状・パーツ配置）  ← L1の頭部に従属
             └─ L4 皮膚・色（部位別質感） ← L0の肌色と連動
                 └─ L5 髪（形状・質・色） ← L3の頭部に従属
                     └─ L6 表情・動作      ← L1の関節に従属
                         └─ L7 衣服フィット ← L2の体表から生成
```

依存の要点:
- L1（骨格）が変わると全層が再生成される。だから骨格
  パラメータは「人物の同一性」の中核としてシードの先頭に
  置く。
- L7（衣服）は独立した資産ではなく L2 の体表からの派生。
  これが自動フィット（§2.6）の構造的な根拠。
- 物理パラメータは L5／L7 の素材選択に従属する（素材を
  選べば係数が決まる）。

### 3.3 利用者に見えるパラメータ数について（正直な注記）

棚卸しの 9,034 は仕様要素の数であり、スライダーの数では
ない。利用者に直接見せる連続パラメータは、顔 109、体型
80、髪 30、色 20、化粧 10 の直接パラメータ 249 に、左右差
軸・系統ブレンド 22・年齢や身長等の全体軸を加えて
**約300** を目標とする。これは inZOI の 250超と数では
同等以上だが、1パラメータあたりの表現の深さ（スキャン
由来の形状変化）では及ばない。数で互角以上、深さで負ける。
その事実を隠さない。

## 5. 段階的実装計画

各フェーズは「到達する範囲」と「検証方法」をセットにする。
検証は一貫して: 単体テスト（不変条件ガードを含む全件合格）、
本番ビルド、Electron ヘッドレス実走での目視確認（証拠スク
リーンショットを evidence/ に保存）、という現行の検証梯子
を使う。

### フェーズ0: パラメータ基盤
- 内容: パラメータベクトルの型と保存形式（現行 Outfit の
  拡張）、シード符号化、複数プリセット保存。
- 到達範囲: CUS の保存・シード系（約10件）と、以後の全
  フェーズの土台。
- 検証: 保存→復元の往復テスト、シードの再現性テスト。

### フェーズ1: 効く核（色・大きさ・動きの基礎）
- 内容: 肌色（フィッツパトリック連続）・髪色・瞳色の
  パラメータ化、身長スライダー（プロファイル再生成＋
  カメラ・ミラーの追従）、ポーズ遷移の補間、まばたきの
  自然化、髪型 3〜4 種の追加。
- 到達範囲: GAP-ANALYSIS トップ10 の 1・2・4・5・7。
  「人が1人ではない」ことが初めて成立する。
- 検証: パラメータ両端での撮影比較（破綻の目視確認）、
  遷移の中間フレーム確認。

### フェーズ2: 顔と目
- 内容: 目の作り直し（白目・虹彩・角膜）＋視線（サッカード
  ・注視・カメラ目線）、顔パラメータの第1弾（目・鼻・唇・
  輪郭の主要約40）、左右差の導入。
- 到達範囲: トップ10 の 3。マネキン感の主要因への対処。
- 検証: 近接撮影での目の読み取り、視線動作の動画相当の
  連続撮影。
- **監査による範囲の確定（§5.8）**: 顔パラメータは「主要
  約40」から **同一性を担う13件** に削減した（変換で表せる
  ものだけを残し、顎幅・顔の長さ等は延期）。左右差は全
  パラメータへのΔ軸ではなく **単一の「左右差」パラメータ**
  （自然な非対称パターンの強さ）に簡素化した。視線はモード
  や UI を作らず、カメラ注視＋サッカードの振る舞いとして
  実装する。表情は引き続き対象外（ゲート G2／DESIGN §9.2
  は不変）。

### フェーズ3: 骨格生成と関節
- 内容: 骨格パラメータから関節階層を生成（脚の関節・首・
  脊柱2段・指の形状と簡易関節）、体型スライダー（太さ・
  筋肉・脂肪の近似連動）、ボトムスと靴のカテゴリ新設。
- 法律・倫理ゲート: G3（LEGAL-ETHICS.md §5.3）。体型
  スライダーと同時にパラメータ安全制限（CUS-0779）の
  実装を必須とし、パラメータの組合せで未成年相当の体型
  を生成できないことを確認する（判断 J-02）。これは
  従来計画への変更である: 安全制限は独立した将来項目
  ではなく、体型可変化と同一フェーズの受け入れ条件に
  する。
- 到達範囲: トップ10 の 6 と勝ち筋 §2.1 の核。座位等の
  ポーズ拡張の下地。
- 検証: 関節可動域での形状破綻チェック（極端ポーズ撮影）、
  体型両端での衣服フィット確認。
- **監査による変更（§5.8）**: 本フェーズは解体した。
  (1) **ボトムスと靴のカテゴリ新設は分離し、フェーズ2の
  次の実装単位へ昇格**した（試着アプリで最も分かりやすい
  欠落であり、骨格機構より先に埋める）。(2) **骨格生成の
  一般機構（骨長ベクトル→関節階層の自動生成、指関節、
  脊柱多段）は削除**した。関節は具体的なポーズや機能が
  要求した時点で局所的に追加する。(3) 体型スライダーは
  プロファイル再生成方式の縮小版として存続し、ゲート
  G3（安全制限 CUS-0779 と同時実装）は不変。

### フェーズ4: 系統ブレンドと遺伝
- 内容: 特徴ごとの系統ブレンド、2体からの遺伝合成、
  シードの共有カード埋め込み、年齢の近似連動（皮膚と
  姿勢のみ、成人の範囲）。
- 法律・倫理ゲート: G4（LEGAL-ETHICS.md §5.3）。計画を
  次のとおり具体化する（判断 J-01／J-02／J-06／J-07）:
  系統プリセット・系統ブレンドの UI に国籍・民族名の
  ラベルを使わない。**年齢連動の下限は外見年齢20歳相当**
  とする（従来の「成人の範囲」の具体化）。**年齢パラ
  メータは遺伝合成の対象に含めず、合成結果は成人として
  提示する**。共有カードには架空の人物である旨を明記
  する。
- 到達範囲: 勝ち筋 §2.2・§2.4・§2.5。作った人物が広がる
  仕組みの完成。
- 検証: ブレンド中間値の破綻確認、遺伝合成の再現性、
  カード経由の復元テスト。
- **監査による変更（§5.8）**: (1) **系統分布ブレンドの
  機構は削除**した。特徴パラメータ自体が利用者の手に渡る
  （フェーズ2）ため、内部の系統分布は「見えない機械」で
  あり、J-01 のカリカチュア化リスクだけが残る。代替は
  パラメータのプリセットとランダム生成（系統ラベルは
  内部にも持たない）。(2) **シードの共有カード埋め込みは
  分離し、フェーズ2の次々単位へ昇格**した（カードこそが
  拡散媒体であり、シード v2 の確定直後に行うのが順序として
  正しい）。(3) 遺伝合成は存続するが順位を下げた（パラ
  メータベクトルの補間として安く実装できる。J-06 の条件
  は不変）。(4) **年齢の近似連動は無期限延期**とした
  （近似のみ・J-02 制約下で共有画像への寄与が小さく、
  リスク面だけが大きい）。
- **実施記録（2026-11-20）**: 遺伝合成は §5.8 優先順位
  5 として実装済み（DESIGN.md §16）。系統分布ブレンド
  と年齢連動は削除・無期限延期のままで、本フェーズの
  残存内容はこれで完了した。ゲート G4 は J-06 の条件
  （架空人物同士のみ・年齢パラメータ不在・子は sanitize
  経由で安全制限が効く・結果は成人として提示・出自を
  記録しない）を実装とテストで固定し通過した。

### フェーズ5: 物理の近似層と自動フィットの一般化
- 内容: 小物・髪のバネ揺れ、スカート裾の揺れ近似、素材
  プリセット（物理係数表）、体型全域への衣服自動フィット
  とサイズ表示。
- 到達範囲: 勝ち筋 §2.6・§2.7。
- 検証: ポーズ変更・回転時の揺れの目視、体型両端での
  貫通チェック。
- **監査による変更（§5.8）**: バネ揺れ等の物理近似は
  **延期**した（共有されるのは静止画であり、揺れはカード

  自動フィットの一般化は体型スライダー（縮小版フェーズ3）
  側へ統合した。

### フェーズ6: 描画の底上げ
- 内容: 法線マップ化、テクスチャ解像度の引き上げ、GTAO
  等の AO、SSS 近似、端末適応の画質スケーリング。
- 到達範囲: REN の「可能〜近似」系の回収。
- 検証: 実機相当の負荷測定（現状は VM のソフトウェア

### 5.8 計画変更履歴: 2026-11-20 マスク思考法＋ソクラテス問答による監査

mi の恒常指示（マスク思考法＋ソクラテス問答法）に基づき、
フェーズ2以降の計画を実行前に問い直した記録である。計画を
黙って変えるのではなく、判断と理由をここに残す。

**問いの立て方**: 本製品の目的は「公開と認知」であり、拡散の
媒体は共有カード（静止画）とシード文字列である。よって各
フェーズ・各項目に「なぜ必要か／間違いならどんな証拠が出る
はずか／やめたら何が起きるか」を問うた。共有されるのは
パラメータの総数ではなく「その人らしい顔とコーデ」である、
という視点で優先順位を組み替えた。

**フェーズ2（顔と目）への問い**:
- なぜ必要か: 人物の同一性は顔にある。現行の顔は単一固定の
  マネキンであり、証拠スクリーンショットは全て「同じ人物」
  である。服と髪と肌色が変わっても人物は同一であり、
  「その人らしい」が成立しない。やめたら、全員のカードが
  同じ顔の着せ替え写真になり、作る楽しみと共有の動機が
  頭打ちになる。→ **存続。最優先のまま**。
- ただし中身は削った: 「顔パラメータ主要約40」の大半は、
  プリミティブ構成のマネキン顔では視覚的な利得が小さい。
  同一性を担うもの（目の大きさ・間隔・高さ・形・傾き、
  眉の高さ・傾き、鼻の幅・高さ、口の幅、唇の厚み、顔の幅）
  の **13件** に削減した。顎幅・顔の長さは現行の Lathe 頭部
  では独立に動かせず（変換で表せない）、頭部の再生成方式が
  入るまで延期する。
- 左右差: 全パラメータにΔ軸を持たせる設計（§2.3）は、
  スライダーとシードを倍増させる割に効果が「自然な非対称
  パターンの有無」に集約できる。**単一の「左右差」パラ
  メータ**（固定パターンの強さ。既定値もゼロにしない）に
  簡素化した。
- 視線: モードや UI は作らない。カメラへの注視とサッカード
  は「振る舞い」であってパラメータではない。カード（静止画）
  ではカメラ目線が効き、アプリ内では微動が生命感になる。

**フェーズ3（骨格生成と関節）への問い**:
- 骨格生成の一般機構について: 画面とカードに届くのは
  シルエットとポーズであり、骨そのものは写らない。最大の
  シルエット軸である身長はフェーズ1で実現済みで、第二の軸
  （太さ）は体型スライダーがプロファイル再生成で担える。
  現行ポーズは全て立位・上半身で、脚関節・脊柱・指関節を
  必要とする機能は存在しない。「間違っているなら証拠が
  出るはず」の証拠（関節不足によるポーズの破綻）は現れて
  いない。→ **一般機構は削除**。関節は具体的なポーズや
  機能が要求した時点で局所的に足す。勝ち筋 §2.1 は
  「骨格を固定する理由がない」という原理の主張としては
  残るが、実装単位としての優先順位は下げた（原理と実装
  順序は別である）。
- ボトムスと靴: 試着アプリでありながら下半身の衣服が
  カテゴリとして存在せず、全てのカードでコーデが未完に
  なる。これは骨格機構より先に埋めるべき欠落である。
  → **フェーズ2の次の実装単位へ昇格**。

**フェーズ4（系統ブレンドと遺伝）への問い**:
- 系統分布ブレンド: フェーズ2で特徴パラメータ自体が利用者
  の手に渡る以上、内部に系統分布を持って特徴を混合する
  機構は利用者から見えない機械であり、得られる顔の多様性
  はパラメータのプリセットとランダム生成で代替できる。
  一方で J-01 のカリカチュア化リスクは機構側に残り続ける。
  → **削除**（系統ラベルは内部にも持たない）。
- シードの共有カード埋め込み: カードこそ拡散媒体であり、
  そこにシードが載れば「画像を見た人がその人物を再現
  できる」往復が成立する。安く、目的に直結する。
  → **フェーズ2の次々単位へ昇格**（シード形式 v2 の確定
  直後に行うのが正しい順序）。
- 遺伝合成: パラメータベクトルの補間として安い。遊びと
  しての共有価値はあるが、顔パラメータの定着が前提。
  → 存続、順位は下げる（J-06 の条件は不変）。
- 年齢連動: 近似のみ、J-02 の制約下では成人の範囲の皮膚・
  姿勢の近似に限られ、マネキン顔のカードでは年齢は読み
  取りにくい。寄与が小さくリスク面だけが大きい。
  → **無期限延期**。

**フェーズ5（物理の近似層）への問い**:
- バネ揺れは静止画のカードに写らない。アプリ内の生命感は
  視線・瞬き・呼吸の揺れが既に担っている。→ **延期**。
  自動フィットの一般化は体型スライダーと不可分なので、
  縮小版フェーズ3へ統合した。

**フェーズ6（描画の底上げ）への問い**:
- 法線マップとテクスチャ解像度は全てのカードに効くが、
  「何が写っているか」（顔とコーデ）が先で、描画の底上げは
  その乗数である。→ 順位は最後のまま据え置き。

**監査後の優先順位**:
1. フェーズ2: 目の作り直し＋視線＋顔パラメータ第1弾
   （13件）＋単一ノブの左右差 ← 本監査の直後に実施
2. ボトムスと靴のカテゴリ新設（旧フェーズ3から分離・昇格）
   ← **実施済み（2026-11-20、DESIGN.md §12）**: スカート／
   パンツ／ショートパンツ＋靴4種。シードは v3 へ
3. シードの共有カード埋め込み（旧フェーズ4から分離・昇格）
   ← **実施済み（2026-11-20、DESIGN.md §12）**: PNG tEXt
   チャンク埋め込み＋カード面へのシード印字と「架空の
   人物」明記（J-07）。復元はドロップ／ファイル選択／
   文字列貼り付けの3経路
4. 体型スライダー（プロファイル再生成方式）＋安全制限
   CUS-0779（旧フェーズ3の縮小版。ゲート G3 は不変）
   ← **実施済み（2026-11-20、DESIGN.md §15）**: 体型パラ
   メータは監査で5件に絞った（肩幅／ウエスト／ヒップ／
   バスト／体格。筋肉量は独立軸として削り体格へ吸収）。
   衣服は体と同じ係数関数（bodyRadiusFactor）を通して
   自動フィットする。安全制限は sanitize の組合せルール
   （youthScore）として全経路に効かせ、ゲート G3 を通過
   した。シードは v4 へ
5. 遺伝合成（J-06 の条件つき）
   ← **実施済み（2026-11-20、DESIGN.md §16）**: 特徴ごと
   の継承／ブレンドを決定的 PRNG で選ぶ合成（離散値は
   継承のみ）。UI はプレビュー→適用の流れ、コマンド層に
   `blend_characters` を追加。子は sanitize 経由で安全
   制限が効き、通常のシード・カードで増殖できる
6. 描画の底上げ（旧フェーズ6）
7. 人物ファイル書き出し（glTF／VRM。監査後の追加単位。
   PERSPECTIVES.md 視点4の目的付け替えにより優先順位6
   より前に実施）
   ← **実施済み（2026-11-20、DESIGN.md §17）**: 書き出
   し専用の一時リグで T ポーズ化し、既知のアンカーと
   設計定数から17関節のヒューマノイド骨格を書き出し時
   に構築（アプリ本体に骨格生成の一般機構は持たない —
   監査の削除判断は不変）。GLB と VRM 1.0 の両形式を
   自作ライタで書き出し、シード＋名前付きパラメータ
   JSON＋利用条件（架空・素材として自由に使える）を
   ファイルに同梱する。VRM の licenseUrl は CC0 1.0
   証書 URL
- 削除: 骨格生成の一般機構、系統分布ブレンドの機構
- 無期限延期: 年齢連動
- 延期: 物理の近似層（バネ揺れ）

## 6. 制約との整合

| 目標 | 制約との関係 | 扱い |
|---|---|---|
| 骨格生成・パラメータ化全般 | コード生成のみで成立 | 目標に含む |
| シード共有・遺伝 | 端末内処理のみ。サーバ不要 | 目標に含む（大原則と両立） |
| 系統ブレンド | 分布パラメータはコード内定義 | 目標に含む（扱いは論点1に従う） |
| 年齢の連続変化 | 成人の範囲に限定 | 目標に含む（限定つき） |
| 国籍・民族名ラベル付きの系統プリセット | LEGAL-ETHICS J-01（カリカチュア化・ステレオタイプ固定化の回避） | **作らない**（系統は内部の分布参照のみ） |
| 未成年相当の人物の生成 | LEGAL-ETHICS J-02（プラットフォーム規範・他法域の法） | **作らない**（年齢は成人範囲に限定＋パラメータ安全制限） |
| 実在人物の再現プリセット／実在ブランドロゴ・意匠 | LEGAL-ETHICS J-08／J-09（肖像・パブリシティ権、商標・著作権） | **作らない**（同梱・公式提供物は全て自作） |
| 未成年を想起させる衣装（学校制服等） | LEGAL-ETHICS J-11 | **作らない** |
| ベースレイヤーを外す操作（裸化） | LEGAL-ETHICS J-10 | **作らない**（ベースレイヤーはマネキンの体表として常時着用） |
