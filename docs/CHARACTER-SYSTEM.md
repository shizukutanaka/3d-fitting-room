## 1. 「凌駕」の定義と比較

### 1.1 定義

「凌駕」を全面勝利とは定義しない。制作体制が桁違いの相手に
描画の実写度で勝てるはずがない。本システムの「凌駕」は
次の4軸で勝つことと定義する:

1. **生成の原理**: ゲームのキャラメイクは「固定骨格＋モーフ
   （あらかじめ作られた形状のブレンド）」が主流。本システムは
   全てコード生成ゆえに、**骨格そのものをパラメータから生成**
   できる。土台から違う。
2. **パラメータ空間の広さと連続性**: 系統ブレンド・非対称・
   年齢を「プリセットの切替」ではなく連続パラメータとして
   持つ。
3. **試着との統合**: 体型が変わっても衣服が自動でフィット
   する。キャラメイク単体のゲームには存在しない、試着室
   ならではの優位。
4. **共有の仕組み**: 人物をシード文字列で表し、サーバなし・
   個人データなしで共有カード経由で広げられる。ゲームの
   ギャラリーは運営サーバが前提で、本作の大原則（作成者は
   個人データを持たない）と両立しない方式は採らない。

逆に、勝てない軸は §1.3 で正直に挙げる。

### 1.3 勝てる軸・勝てない軸（結論）

**勝てる軸**:
- 骨格の生成原理（固定骨格＋モーフへの構造的な差）。
- 試着との統合（自動フィット）。キャラメイクのゲームは
  「作って終わり」で、服合わせが主目的の道具ではない。
- 共有の軽さ（シード＋カード、サーバ・登録・アカウント不要）。
  これは大原則（個人データゼロ）から自然に生まれる優位。
- 入口の軽さ（ブラウザで即時、無料、インストール不要）。

**勝てない軸**（目標から外すか近似に留める）:
- 描画の実写度。スキャン素材と専用エンジンが前提の領域で、
  コード生成のみでは届かない（棚卸しの「近似のみ」が全体の
  84%を占める事実と一致する）。
- 表情・演技の厚み（モーションキャプチャとフェイシャル
  リグの制作体制の差）。
- 本格的な布・髪の物理（自己衝突を含むものは「不可能」296件
  の主因）。
- 素材・髪型・服のライブラリ量（運営が継続追加する体制の差）。

## 2. 勝ち筋の設計

### 2.1 骨格そのものから生成する

- 仕組み: 骨長と比率のパラメータベクトルから関節位置を算出
  し、体表プロファイル（現行の Lathe 制御点列）を骨格に
  従属させる。現行コードは既に「プロファイル列→回転体」と
  いう生成構造を持っており、これを「固定プロファイル」から
  「骨格パラメータで駆動されるプロファイル」へ一般化する。
- なぜ勝てるか: ゲーム側はアセット保護とアニメーション
  資産の再利用のため骨格を固定せざるを得ない。本作は
  アニメーション資産を持たない（弱みでもある）が、裏返せば
  骨格を固定する理由がない。
- 作れる範囲: 骨長・比率の可変と、それに連動する体表・
  アンカー・衣服の再生成まで。「可能〜近似」。解剖学的に
  正確な骨形状そのものは作らない（体表に出ない内部構造に
  制作資源を割かない判断）。
- 対応する棚卸し: SKE 骨・長さ／太さ系 412 件、BDY 身長連動
  24 件。

### 2.2 民族系統の連続ブレンド

- 仕組み: 系統を「完成品プリセット」ではなく、特徴ごと
  （肌色、目の形、鼻、唇、頬骨、髪質…）の分布パラメータと
  して持ち、特徴ごとに混合率を指定して合成する。GTA Online
  の遺伝（両親ブレンド）を、特徴単位・N系統へ一般化した形。
- なぜ勝てるか: 多くのゲームは系統をプリセット選択で済ま
  せる。本作は特徴単位の混合率まで連続化する。
- 作れる範囲: 肌色・色調は「可能」。顔立ち・髪質は「近似
  のみ」（プリミティブ顔の解像度の限界）。扱いの配慮は
  GAP-ANALYSIS.md §4 の論点1のとおり（系統は分布の参照で
  あって国籍ラベル付き完成品にしない）。

### 2.3 左右非対称の導入

- 仕組み: 全ての対パラメータに左右差（Δ）軸を持たせる。
  実在の顔と体は非対称であり、完全対称は「作り物感」の
  主要因のひとつ。自然な範囲のランダム非対称を初期値に
  混ぜる。
- なぜ勝てるか: 非対称編集を持つゲームは少数（inZOI、
  黒い砂漠等）で、体全体に一貫した非対称軸を持つものは
  さらに少ない。
- 作れる範囲: 「可能」。パラメータ構造の問題であり、描画
  技術の問題ではない。対応: FAC 左右差系 144 件（12パラ
  メータ×12系統）＋ BDY 左右差系。

### 2.4 年齢の連続変化

- 仕組み: 年齢パラメータ（連続値）が、骨格（姿勢・脊柱の
  湾曲）、体型（脂肪分布）、皮膚（しわ・たるみ・色調）に
  連動する。年齢「区分」ではなく連続であることが差。
- 作れる範囲: 「近似のみ」。皮膚テクスチャ側の連動と姿勢
  の連動は届くが、成長（若年層の体格変化）まで含めるかは
  GAP-ANALYSIS.md §4 の論点3（安全・倫理面の判断事項）
  であり、本設計では成人の範囲内の連続変化を対象とする。

### 2.5 2体からの「遺伝」合成とシード共有

- 仕組み: 人物全体をパラメータベクトルとしてシード文字列
  に符号化する（端末内のみで生成・保存）。2体のベクトルを
  特徴グループごとの混合率で補間すれば「遺伝」になる。
  共有は既存の共有カード（PNG）にシードを併記／埋め込む
  形で、受け取った側が端末内で再現する。サーバは要らない。
- なぜ勝てるか: ゲームの共有は運営サーバのギャラリーが
  前提。本作は「画像ファイル自体が媒体」という既存の製品
  設計（DESIGN.md §1）と直結し、大原則と矛盾しない。
- 作れる範囲: 「可能」。対応: CUS システム系のシード・
  遺伝系 7 件＋パラメータの対象化 747 件。

### 2.6 試着との統合（自動フィット）

- 仕組み: 現行の衣服生成は「体プロファイル＋約11mmオフ
  セット」という生成方式であり、体型パラメータが変われば
  オフセット元を差し替えて再生成できる。つまり自動フィット
  は現行アーキテクチャの一般化として設計できる。フィット
  結果はサイズ表示（S/M/L 等）に翻訳して「試着」らしく見せる。
- なぜ勝てるか: キャラメイクのゲームに試着という概念が
  ない。本作の存在理由そのものが優位になる唯一の軸。
- 作れる範囲: 「近似のみ」（布の物理的なフィットではなく
  形状の追従）。対応: CLO フィット系＋CUS 自動フィット系。

### 2.7 物理のメイク時プレビュー

- 仕組み: 本格物理ではなく、近似物理（小物の回転バネ、髪の
  遅延追従、裾の揺れ）をメイク画面でそのまま見せる。作った
  人物が「動いたときどう見えるか」を作る時点で確認できる。
- 作れる範囲: 「近似のみ」。自己衝突・本格布は §6 のとおり
  目標から外す。対応: PHY 小物 32 件・髪 36 件が中心。

### 3.2 階層と依存関係

```
L0 系統ブレンド（特徴ごとの混合率）
 └─ L1 骨格（骨長・比率・関節位置）        ← 全ての土台
     └─ L2 体型（脂肪・筋肉・姿勢・年齢）   ← L1に従属
         └─ L3 顔（頭部形状・パーツ配置）  ← L1の頭部に従属
             └─ L4 皮膚・色（部位別質感） ← L0の肌色と連動
                 └─ L5 髪（形状・質・色） ← L3の頭部に従属
                     └─ L6 表情・動作      ← L1の関節に従属
                         └─ L7 衣服フィット ← L2の体表から生成
```

依存の要点:
- L1（骨格）が変わると全層が再生成される。だから骨格
  パラメータは「人物の同一性」の中核としてシードの先頭に
  置く。
- L7（衣服）は独立した資産ではなく L2 の体表からの派生。
  これが自動フィット（§2.6）の構造的な根拠。
- 物理パラメータは L5／L7 の素材選択に従属する（素材を
  選べば係数が決まる）。

### 3.3 利用者に見えるパラメータ数について（正直な注記）

棚卸しの 9,034 は仕様要素の数であり、スライダーの数では
ない。利用者に直接見せる連続パラメータは、顔 109、体型
80、髪 30、色 20、化粧 10 の直接パラメータ 249 に、左右差
軸・系統ブレンド 22・年齢や身長等の全体軸を加えて
**約300** を目標とする。これは inZOI の 250超と数では
同等以上だが、1パラメータあたりの表現の深さ（スキャン
由来の形状変化）では及ばない。数で互角以上、深さで負ける。
その事実を隠さない。

## 5. 段階的実装計画

各フェーズは「到達する範囲」と「検証方法」をセットにする。
検証は一貫して: 単体テスト（不変条件ガードを含む全件合格）、
本番ビルド、Electron ヘッドレス実走での目視確認（証拠スク
リーンショットを evidence/ に保存）、という現行の検証梯子
を使う。

### フェーズ0: パラメータ基盤
- 内容: パラメータベクトルの型と保存形式（現行 Outfit の
  拡張）、シード符号化、複数プリセット保存。
- 到達範囲: CUS の保存・シード系（約10件）と、以後の全
  フェーズの土台。
- 検証: 保存→復元の往復テスト、シードの再現性テスト。

### フェーズ1: 効く核（色・大きさ・動きの基礎）
- 内容: 肌色（フィッツパトリック連続）・髪色・瞳色の
  パラメータ化、身長スライダー（プロファイル再生成＋
  カメラ・ミラーの追従）、ポーズ遷移の補間、まばたきの
  自然化、髪型 3〜4 種の追加。
- 到達範囲: GAP-ANALYSIS トップ10 の 1・2・4・5・7。
  「人が1人ではない」ことが初めて成立する。
- 検証: パラメータ両端での撮影比較（破綻の目視確認）、
  遷移の中間フレーム確認。

### フェーズ2: 顔と目
- 内容: 目の作り直し（白目・虹彩・角膜）＋視線（サッカード
  ・注視・カメラ目線）、顔パラメータの第1弾（目・鼻・唇・
  輪郭の主要約40）、左右差の導入。
- 到達範囲: トップ10 の 3。マネキン感の主要因への対処。
- 検証: 近接撮影での目の読み取り、視線動作の動画相当の
  連続撮影。

### フェーズ3: 骨格生成と関節
- 内容: 骨格パラメータから関節階層を生成（脚の関節・首・
  脊柱2段・指の形状と簡易関節）、体型スライダー（太さ・
  筋肉・脂肪の近似連動）、ボトムスと靴のカテゴリ新設。
- 到達範囲: トップ10 の 6 と勝ち筋 §2.1 の核。座位等の
  ポーズ拡張の下地。
- 検証: 関節可動域での形状破綻チェック（極端ポーズ撮影）、
  体型両端での衣服フィット確認。

### フェーズ4: 系統ブレンドと遺伝
- 内容: 特徴ごとの系統ブレンド、2体からの遺伝合成、
  シードの共有カード埋め込み、年齢の近似連動（皮膚と
  姿勢のみ、成人の範囲）。
- 到達範囲: 勝ち筋 §2.2・§2.4・§2.5。作った人物が広がる
  仕組みの完成。
- 検証: ブレンド中間値の破綻確認、遺伝合成の再現性、
  カード経由の復元テスト。

### フェーズ5: 物理の近似層と自動フィットの一般化
- 内容: 小物・髪のバネ揺れ、スカート裾の揺れ近似、素材
  プリセット（物理係数表）、体型全域への衣服自動フィット
  とサイズ表示。
- 到達範囲: 勝ち筋 §2.6・§2.7。
- 検証: ポーズ変更・回転時の揺れの目視、体型両端での
  貫通チェック。

### フェーズ6: 描画の底上げ
- 内容: 法線マップ化、テクスチャ解像度の引き上げ、GTAO
  等の AO、SSS 近似、端末適応の画質スケーリング。
- 到達範囲: REN の「可能〜近似」系の回収。
- 検証: 実機相当の負荷測定（現状は VM のソフトウェア
  レンダリングのみが前提のため、実機確認は別途 mi の
  環境が必要——これは未検証として残る）。

## 6. 制約との整合

| 目標 | 制約との関係 | 扱い |
|---|---|---|
| 骨格生成・パラメータ化全般 | コード生成のみで成立 | 目標に含む |
| シード共有・遺伝 | 端末内処理のみ。サーバ不要 | 目標に含む（大原則と両立） |
| 系統ブレンド | 分布パラメータはコード内定義 | 目標に含む（扱いは論点1に従う） |
| 年齢の連続変化 | 成人の範囲に限定 | 目標に含む（限定つき） |
| 本格布シミュレーション（自己衝突込み） | モバイル WebGL と両立しない | **不可能。目標から外す**（近似のみ） |
| ストランド級の髪 | 制作・描画コストが制約を超える | **不可能。目標から外す**（シェル＋カード近似まで） |
| リアルタイム GI | WebGL の範囲外 | **不可能。目標から外す**（IBL で代替済み） |
| スキャン級の皮膚・顔 | 外部素材ゼロと矛盾 | **不可能。目標から外す**（近似まで） |
| 表情の本格演技（モーキャプ級） | 制作体制の差 | **不可能。目標から外す**（視線・瞬き等の近似まで） |
| 運営サーバ型ギャラリー | 個人データゼロの大原則と矛盾 | **作らない**（シード＋カードで代替） |
| 課金・広告・解析 | 金ゼロ・個人データゼロ | **作らない**（不変条件テストで固定済み） |
